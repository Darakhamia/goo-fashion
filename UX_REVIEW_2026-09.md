Планка по анимации взята не из головы: это набор скилов Anthropic
(`improve-animations`, `emil-design-eng`, `apple-design`, `review-animations`),
кодифицирующий подход Эмиля Ковальски — восемь категорий аудита, точные значения кривых
и длительностей. Каждое утверждение ниже перепроверено по коду, номера строк —
на коммите `86ebeb7`. Где судить по коду нельзя (ощущение кроссфейда, упругость пружины) —
это сказано прямо, и в DoD стоит проверка глазами, а не чтение диффа.

### Чего в обзоре нет

# Блок Д — дизайн

## Д1. Клавиатурная навигация невидима на всём сайте

**HIGH.** Пересекается с `DESIGN_SYSTEM.md` §11 (high), перепроверено 8 сентября — стоит.

Факты по коду:

- `outline-none` — **55 вхождений** в `src/`.
- `:focus-visible` — **2 вхождения**, оба нерабочие: одно в мёртвом `src/components/ui/button.tsx:8`
  (его единственный импортёр `blocks/hero-section-1.tsx` сам никем не импортируется, см. С3),
  второе — совпадение в бинарном файле.
- В `globals.css` — **ни одного** правила `:focus-visible`.

То есть человек, идущий по сайту с клавиатуры, не видит, где он находится:
ни в каталоге, ни в карточке товара, ни в билдере, ни в форме оплаты.
В админке (`goo-studio/users/page.tsx:101`) фокус-стилей тоже нет — включая кнопку
массового удаления.

Это не только вопрос вкуса: это доступность и это оплата — `/subscribe` проходится с клавиатуры вслепую.

**Что делать.** Одно правило в `globals.css`, до всякой чистки `outline-none`:

```css
:focus-visible {
  outline: 2px solid var(--border-strong);
  outline-offset: 2px;
  border-radius: 2px;
}
```

Затем пройти 55 `outline-none` и оставить их только там, где рядом есть собственная
замена фокуса. `:focus-visible` не срабатывает на клик мышью, поэтому визуальной
регрессии для мышиного сценария быть не должно.

**DoD.** Пройти Tab-ом три маршрута — `/browse`, `/product/[id]`, `/subscribe` — и снять
скриншоты трёх состояний фокуса. Проверить, что при клике мышью кольцо не появляется.
Утверждение «фокус видно» без снимков не принимается.

# Блок А — анимация

Планка: `improve-animations` / `emil-design-eng`. Восемь категорий, точные значения.

## А1. `PageTransition` — 350 мс налога на каждый переход

**HIGH. Самый высокий рычаг во всём обзоре: один файл, 20 строк.**

`src/components/ui/PageTransition.tsx` целиком:

```tsx
<motion.div
  key={pathname}
  initial={{ opacity: 0, y: 8 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.35, ease: [0.22, 1, 0.36, 1] }}
>
```

Смонтирован в `ConditionalSiteLayout.tsx:65` — то есть **вокруг всего сайта**.
Четыре независимые проблемы в двадцати строках:

1. **Частота.** Переход между страницами — действие из категории «десятки раз за сессию».
   По планке (`AUDIT.md` §1) такое либо не анимируется, либо анимируется сильно короче.
   350 мс платятся при каждом клике по навигации.
2. **Задерживается ровно то, что уже готово.** Контент приезжает с сервера и держится
   прозрачным ещё треть секунды. Визуальный LCP отодвигается на 350 мс — при том, что
   технически страница уже отрисована.
3. **`y: 8` — shorthand Framer Motion, он не аппаратно ускорен** (`AUDIT.md` §5):
   идёт через `requestAnimationFrame` в главном потоке — том самом, который в этот момент
   занят гидратацией нового маршрута. Это буквально случай, который Ковальски описывает
   на примере дашборда Vercel: кадры сыпятся именно при загрузке.
4. **Transform на обёртке всей страницы создаёт containing block** — на время анимации
   `position: fixed` внутри считается от неё, а не от вьюпорта. Хедер, мобильная нижняя
   навигация и открытые оверлеи в эти 350 мс позиционируются от смещённого предка.

Плюс `key={pathname}` без `AnimatePresence` (проверено: `AnimatePresence` в проекте есть,
но ни разу не обёрнут вокруг `PageTransition`) — выхода нет вообще: старая страница
исчезает мгновенно, новая всплывает. Асимметрия не в ту сторону.

**Что делать — три варианта, решает CEO (см. Развилку 2).**

- **(а) Удалить.** Переходы становятся мгновенными. Мой выбор: 350 мс на действие,
  которое делают десятки раз, ничего не объясняют — спатиальной связи между двумя
  страницами тут нет.
- **(б) Сократить до чистой прозрачности, 150 мс.** Без `y`, без transform на обёртке:
  снимает пункты 3 и 4 целиком, оставляет мягкость.
- **(в) Оставить как есть** — если это осознанное решение о характере сайта. Тогда
  как минимум убрать `y` и перевести на CSS-переход, чтобы уйти из главного потока.

**DoD.** Замерить LCP на `/browse` и `/product/[id]` до и после (Lighthouse, три прогона,
медиана). Записать обе цифры. Отдельно — профиль Performance при переходе:
подтвердить, что дропнутых кадров стало не больше.

## А2. Кнопка не отвечает на нажатие

**HIGH.** Точные числа по коду:

- `<button>` в `src/` — **501**
- утилит `active:` любых — **37**
- из них `active:scale` (собственно отклик на нажатие) — **13**
- из этих 13: **12 в `builder/page.tsx`**, одна в `MobileBottomNav.tsx`

То есть отклик на нажатие есть **ровно в двух файлах из 116**. Весь публичный сайт —
навигация, карточки товара и образа, корзина, `/plans`, `/subscribe`, фильтры каталога,
стилист — на нажатие не реагирует никак. Палец опускается, ничего не происходит,
через 200–600 мс приезжает новый экран.

Планка (`emil-design-eng`, «Buttons must feel responsive»): `transform: scale(0.97)`
на `:active`, переход `transform 160ms ease-out`, диапазон 0.95–0.98.

Единственная кнопка вне билдера, у которой отклик есть, из диапазона выбивается:
`MobileBottomNav.tsx` — `active:scale-90`. Это заметно резче, чем нужно, и это главная
навигация на телефоне.

**Что делать.** Это одна из немногих правок, которая почти целиком делается один раз
в `globals.css`, не трогая 486 мест:

```css
button:not(:disabled),
[role="button"]:not([aria-disabled="true"]) {
  transition: transform 160ms cubic-bezier(0.23, 1, 0.32, 1);
}
button:not(:disabled):active,
[role="button"]:not([aria-disabled="true"]):active {
  transform: scale(0.97);
}
```

Дальше — точечные исключения: элементы, у которых `transform` уже занят
(карточки с hover-зумом, `MobileBottomNav` со своим `scale-90`), и элементы,
где нажатие не должно давать физического отклика.

**Осторожно:** правило `transition: transform` на всех кнопках взаимодействует с А3
(`transition-all` перекрывает его в 124 местах) и с А7 (глобальный
`transition-duration: 0.001ms !important` под reduced-motion его срежет — это как раз
правильно и трогать не надо). Порядок: А3 → А2.

**DoD.** Снять видео нажатия на телефоне (реальном, не эмуляторе) на четырёх
поверхностях: карточка товара, «Добавить в корзину», кнопка тарифа на `/plans`,
таб нижней навигации. Проверить в замедлении, что отклик читается и что нигде
не воюет с hover-зумом.

## А3. `transition-all` — 124 раза в 36 файлах

**HIGH.** По планке (`AUDIT.md` §5) `transition: all` — находка всегда, без исключений.
Он анимирует свойства, которые анимировать не собирались, включая layout-свойства,
мимо GPU.

Распределение:

| Файл | Вхождений |
|---|---|
| `src/app/builder/page.tsx` | 38 |
| `src/app/browse/page.tsx` | 10 |
| `src/components/layout/Navigation.tsx` | 8 |
| `src/components/product/ProductClient.tsx` | 6 |
| `src/app/profile/page.tsx` | 6 |
| `src/components/stylist/StylistDrawer.tsx` | 5 |
| ещё 30 файлов | 51 |

Хуже всего в билдере: 38 `transition-all` на экране, где одновременно живут перетаскивание,
фильтры и превью — то есть там, где кадры и так на пределе (`AUDIT_DEV_PLAN.md` Б10-1
уже фиксирует 4.9 МБ на мобильном).

Рядом — родственная находка: `.link-underline` (`globals.css:255-269`, 8 файлов)
анимирует `width` с 0 до 100% за 0.3 s. `width` — layout-свойство: каждый кадр
пересчитывает раскладку. Правильно — `transform: scaleX()` с `transform-origin: left`.

**Что делать.** Механическая замена по типу элемента:
`transition-colors` (цвет/фон/граница), `transition-transform` (движение),
`transition-opacity` (прозрачность), `transition-[transform,opacity]` (оба).
Это не творческая работа — её можно отдать любому агенту, у 90% случаев тип очевиден из соседних классов.

**DoD.** `grep -ro 'transition-all' src --include=*.tsx | wc -l` → `0`.
Eslint-правило, запрещающее `transition-all`, рядом с существующими. Профиль Performance
на `/builder`: доля кадров дольше 16 мс при открытии панели фильтров — до и после.

## А7. `prefers-reduced-motion` вырубает всё подряд

**MEDIUM.** `globals.css` (конец файла):

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
    scroll-behavior: auto !important;
  }
}
```

Что здесь правильно: это надёжно, покрывает инлайновые `<style>` и не даёт забыть
про новую анимацию. `DESIGN_SYSTEM.md` §7 фиксирует это как осознанное решение,
и как **защитная сетка** оно хорошее.

Что здесь неверно по планке (`AUDIT.md` §6): «reduced motion — это меньше и мягче
движения, а не ноль». Правило рубит `transition-duration` у **всего**, включая переходы
цвета, прозрачности и подсветки фокуса — то, что не вызывает вестибулярных проблем
и помогает понять, что происходит. Человек, включивший «уменьшить движение»,
получает интерфейс, который не отвечает вообще ничем: ни hover, ни нажатие,
ни появление панели.

Заодно это срежет отклик кнопки из А2 — и вот это как раз правильно и нужно оставить.

**Что делать.** Сузить действие правила до движения, оставив цвет и прозрачность:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    scroll-behavior: auto !important;
    /* движение — убрать, прозрачность и цвет — оставить */
    transition-property: opacity, color, background-color, border-color, box-shadow !important;
    transition-duration: 150ms !important;
  }
}
```

Непрерывные rAF-циклы (`FloatLoop`, `gooey-text-morphing`, `etheral-shadow`,
`HomeFullPageScroll`) гасят себя сами — это уже сделано и это правильно, глобальное
правило их всё равно не остановило бы.

**DoD.** Включить «уменьшить движение» в системе и пройти четыре сценария: hover по
карточке (цвет меняется, зума нет), нажатие кнопки (цвет отвечает), открытие
`UpgradeModal` (появляется без движения), скролл главной (обычный, без перехвата).
Проверить, что бесконечные анимации остановлены, а не ускорены.

## С6. Один файл невидим для всех поисков по коду

**MEDIUM. Находка не про дизайн — про то, что аудит этого файла не увидел.**

`src/app/goo-studio/categories/page.tsx:68`:

```ts
const NEW_BUCKET = "\x00new-bucket";
```

Это **настоящий байт NUL внутри исходника**, а не экранированная последовательность.
Проверено: `tr -dc '\000' < file | wc -c` → `1`, смещение 3046, строка 68.
`file` определяет файл как `data`, а не как текст.

Замысел понятен и разумен: сентинел, который заведомо не столкнётся с настоящим
именем категории. Работает. Но цена — не та, которую платили осознанно:

- **`grep` и `ripgrep` считают файл бинарным и молча его пропускают.** Каждый
  общерепозиторный поиск обходит его стороной. В том числе — все сверки этого обзора:
  из-за него счёт кнопок сначала получился **486** вместо **501**, и 15 кнопок,
  600 строк кода и неизвестное число `transition-all` в подсчёты не попали.
  Все цифры в этом документе приведены по текстовым файлам и занижены ровно на этот файл.
- Любой будущий аудит — хоть человеком, хоть агентом — наступит на те же грабли,
  и не узнает об этом: `grep` не сообщает об ошибке, он просто не находит.
- Часть редакторов и форматтеров такой байт съедает или ломает при сохранении.

**Что делать.** Заменить сентинел на печатаемый, который так же не может столкнуться
с данными: отдельное поле состояния вместо магической строки, либо значение вида
`"__new_bucket__"` с проверкой на входе. Смысл сохраняется, файл возвращается
в зону видимости инструментов.

**DoD.** `file src/app/goo-studio/categories/page.tsx` → `text`, а не `data`.
`grep -c '<button>' ` по файлу работает без флага `-a`. Выбор категории и создание
новой в админке проверены руками: новый bucket создаётся, существующий выбирается.
