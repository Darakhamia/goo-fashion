# Стенд снимков публичного сайта

Снимает страницы и открытые панели публичного сайта на телефоне и десктопе без доступа к Clerk, Supabase и другим сервисам. Считает замеры из `docs/MOBILE_PLAN.md`. Нужен мобильному треку (`docs/MOBILE_ROADMAP.md`), чтобы проверять задачи снимками «до» и «после» и цифрами.

## Как устроено

- **`setup.sh`** запускает `scripts/admin-screens/setup.sh` в своей папке и на своём порту. По умолчанию это `/tmp/goo-site-screens` и `:3200`, переопределяется через `SITE_SCREENS_DIR` и `SITE_SCREENS_PORT`. Стенд админки при этом можно держать запущенным рядом. Временная копия рабочего дерева такая же, как у админки:
  - Clerk подменён заглушкой — вошедший пользователь с тарифом Pro;
  - proxy пропускает всё.

  Затем `setup.sh` правит в копии ещё одно место. Без Supabase страница товара не находит товар, потому что у `getProductById` нет демо-запаса. Копия берёт товар из встроенного демо-каталога.

  **Репозиторий не меняется. Правки копии в `src/` не переносить.**
- **Данные** — встроенный демо-каталог: 24 товара, образы `o-001`…, три статьи журнала. Своих фикстур у стенда нет: публичные API работают на демо-данных, а API, которым нужна база, отвечают ошибкой, как без базы.
- **Баннер cookies.** Он есть только при настроенной аналитике, поэтому `setup.sh` задаёт фиктивный `NEXT_PUBLIC_POSTHOG_KEY`. `shoot.js` записывает на всех страницах отказ от cookies (`"declined"`). Исключение — состояние `cookie-banner`, где согласия нет и баннер виден. Никуда ничего не отправляется.
- **Внешние запросы глушатся.** Фото товаров заменяются цветными заглушками, поэтому на снимках прямоугольники вместо одежды.
- **Подсказка разработчика Next.js** (значок «N») на снимках скрыта.

## Запуск

```bash
bash scripts/site-screens/setup.sh
NODE_PATH=/tmp/goo-site-screens/pw/node_modules \
  node scripts/site-screens/shoot.js --only=browse,product --theme=both --vp=mobile
```

**Параметры:**
- `--only` — имена страниц или состояний через запятую; без него снимается всё.
- `--theme` — `dark` (по умолчанию: так сайт видит новый посетитель) | `light` | `both`.
- `--vp` — экран:
  - `phone` (390×844, по умолчанию);
  - `small` (360×800);
  - `desktop` (1440×900);
  - `mobile` (phone и small);
  - `all` (все три).
- `--full` — пролистать страницу до конца, чтобы сыграли появления при прокрутке, и снять её целиком.
- `--out` — папка для снимков; по умолчанию `$TMPDIR/goo-site-screens/shots`.
- `--metrics` — вместо снимков таблица замеров первого экрана; она же пишется в `metrics.json` рядом со снимками. Колонки:
  - `caps` — надписи капсом;
  - `buttons` — кнопки;
  - `small40` / `small44` — кнопки и ссылки меньше 40 / 44 px по одной из сторон;
  - `firstCardTop` — где начинается первая карточка товара или образа;
  - `header` — низ шапки;
  - `nav` — высота нижней панели;
  - `chrome` — шапка и нижняя панель вместе;
  - `pageWidth` — ширина страницы.
- `--overflow` — вместо снимков список того, что едет вбок: страница или блок, который прокручивается по горизонтали, и элементы за правым краем экрана. Печатает «fits», если всё в порядке. Смысл — с `--vp=small`.

Имена файлов: `<страница>--<тема>-<экран>.png`, при `--full` с суффиксом `-full`.

## Имена

- **Страницы:** `home`, `browse`, `product`, `outfit`, `builder`, `blog`, `article`, `saved`, `profile`, `plans`, `subscribe`, `cart`, `about`, `privacy`, `terms`, `cookie-policy`, `refund`, `sitemap`, `not-found`, `login`.
- **Состояния:**
  - `ai` — открыт AI-стилист;
  - `cart-panel` — панель корзины;
  - `filters` — фильтры каталога;
  - `search` — поиск каталога;
  - `outfits` — вкладка образов;
  - `catalog-empty` — `/api/products` отвечает пустым списком;
  - `catalog-error` — `/api/products` отвечает 500;
  - `product-stores` — страница товара, прокрученная к «Where to buy»;
  - `builder-filters` — фильтры конструктора (только телефон: на десктопе фильтры открыты всегда);
  - `cookie-banner` — главная без сохранённого согласия на cookies.

Состояния находят кнопки по имени, а где имя меняется по ходу трека, ищут и старое, и новое: «Open cart» и «Open bag».

## Ограничения

- `/look/[id]` не снимается: образы пользователей живут в базе, без неё страница отвечает 404.
- Вход (`/login`) снимается без самой формы Clerk: заглушка её не рисует.
- Замеры зависят от демо-каталога. Сравнивать «до» и «после» можно, а прод на этих числах выглядит иначе.
