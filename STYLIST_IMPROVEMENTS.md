# AI Stylist — журнал улучшений

Журнал работ по доработке AI-стилиста. Каждый блок описывает проблему, что
сделано и какие файлы затронуты. Ведётся по мере правок.

## Исходные слабые места (аудит 2026-06-04)

1. **Поиск примитивный** — вместо обещанного pgvector работает full-text search
   + ручной словарь категорий (~100 слов). Запросы вне словаря промахиваются.
2. **Модель/формат вызова** — `gpt-4o-mini` через Replicate, история склеивается
   в plain-text prompt без ролей → нестабильное соблюдение инструкций.
3. **Мобилка без стилиста** — `FloatingStylist` скрыт на мобильных (`hidden md:flex`).
4. **Документация врёт** — `AI_ARCHITECTURE.md` обещает Llama + эмбеддинги, в коде
   gpt-4o-mini + FTS.
5. **Хрупкий контракт «текст + JSON»** — если модель забыла JSON-блок или написала
   ID в тексте, рекомендации теряются.

### Блок 1 (фикс 3) — таймаут на эмбеддинг запроса в чате (2026-06-04)

**Симптом.** После включения семантики чат «думал» минутами. Причина — модель
BGE на Replicate scale-to-zero: первый запрос после простоя делает **холодный
старт** (Starting несколько минут), а чат ждал эмбеддинг синхронно.

**Сделано.**
- `src/lib/server/replicate-ai.ts`: `embedText()` принимает `{ timeoutMs }` и
  через `Promise.race` перестаёт ждать по таймауту (возвращает `null`).
  Предсказание при этом дорабатывает в фоне и «прогревает» модель.
- `src/app/api/stylist/chat/route.ts`: семантический эмбеддинг запроса
  вызывается с `SEMANTIC_EMBED_TIMEOUT_MS = 3500` → при холодном старте чат
  мгновенно отвечает через FTS, семантика подключится, когда модель тёплая.

**Файлы:** `src/lib/server/replicate-ai.ts`, `src/app/api/stylist/chat/route.ts`.

### Блок 1 (фикс 2) — устойчивость бэкфилла к rate limit Replicate (2026-06-04)

**Симптом.** На бэкфилле прилетал `429 Too Many Requests` («rate limit reduced
to 60/min, burst 5 while you have less than $10 in credit»). Часть батча
успевала пройти (48/50), но клиентский цикл падал.

**Сделано.** `src/app/api/admin/embeddings/route.ts` отличает 429 от реальных
ошибок: при throttling батч останавливается, уже сгенерированные строки
сохранены, ответ содержит `throttled: true` и `retryAfter` (секунды, из текста
ошибки Replicate). Клиент по этому полю делает паузу и продолжает.

**Операционно:** корневая причина — баланс Replicate <$10 (жёсткий throttle).
Пополнение до ≥$10 снимает лимит; иначе бэкфилл идёт медленнее с паузами.

**Файлы:** `src/app/api/admin/embeddings/route.ts`.

### Блок 1 (фикс) — генерация эмбеддингов падала (2026-06-04)

**Симптом.** `POST /api/admin/embeddings` возвращал `processed: 0, failed: N` —
эмбеддинги не генерировались.

**Причины и фикс.** В `src/lib/server/replicate-ai.ts`:
- модель `nateraw/bge-large-en-v1.5` теперь вызывается **с пином версии**
  (`:9cf9f015…`) — у community-моделей Replicate без хеша версии вызов не
  проходит;
- добавлены явные параметры `convert_to_numpy: false`, `normalize_embeddings: true`
  (иначе на выходе мог быть URL на numpy-файл вместо массива);
- `embedTextOrThrow()` теперь бросает информативную ошибку (включая образец
  сырого вывода), `embedText()` — безопасная обёртка, возвращающая `null`.
- `src/app/api/admin/embeddings/route.ts` собирает и возвращает `firstError`,
  чтобы реальную причину было видно прямо в ответе эндпоинта.

**Файлы:** `src/lib/server/replicate-ai.ts`, `src/app/api/admin/embeddings/route.ts`.

### Блок 1 — релевантность поиска (2026-06-04)

**Диагноз.** Семантический поиск был «бумажным»: миграция 005 создаёт колонку
`embedding vector(1024)` и функцию `match_products`, но **ничто их не заполняло
и не вызывало** — не было ни хелпера эмбеддингов, ни эндпоинта генерации, а
чат-роут использовал только FTS + словарь категорий. Запросы по поводу
(«на свидание», «в офис») промахивались мимо категорий.

**Сделано (полный путь, как правильнее).**
1. `src/lib/server/replicate-ai.ts`: добавлен `embedText()` (модель
   `nateraw/bge-large-en-v1.5`, 1024 dims, как в миграции 005) и `EMBEDDING_DIMS`.
   Возвращает `null` при любой ошибке/неожиданной форме → graceful-деградация.
2. `src/app/api/admin/embeddings/route.ts` (новый): `POST` бэкфиллит эмбеддинги
   батчами (only `embedding IS NULL`, 25 за вызов, cap 100), `GET` показывает
   покрытие (`total / withEmbedding / missing / coverage`). Защищён `requireAdmin`.
3. `src/app/api/stylist/chat/route.ts`: в `findRelevantProducts()` добавлен
   источник (2) — семантический поиск через `match_products` с порогом
   `SEMANTIC_MIN_SIMILARITY = 0.3`. Best-effort: ошибки/отсутствие эмбеддингов
   не ломают запрос. Источники мёрджатся: категория → семантика → FTS → recency.
4. Маппинг поводов/интентов `OCCASION_STEMS` в `augmentQuery()` — переводит
   «свидание/офис/спорт/пляж/…» (RU+EN, по стемам) в style-термины, которые
   реально есть в описаниях/keywords. Помогает и FTS, и эмбеддинг-запросу.

**Эффективность.** Семантика опт-ин через env `STYLIST_SEMANTIC_SEARCH=1`,
чтобы не тратить embed-вызов на каждый запрос до бэкфилла.

**⚠️ Операционные шаги для активации семантики:**
1. Применить миграцию 005 в проде (pgvector + `match_products`).
2. Прогнать `POST /api/admin/embeddings` (повторять, пока `done: true`).
3. Выставить env `STYLIST_SEMANTIC_SEARCH=1`.

**Файлы:** `src/lib/server/replicate-ai.ts`, `src/app/api/admin/embeddings/route.ts`,
`src/app/api/stylist/chat/route.ts`.

### Блок 3 — мобильный доступ / мёртвый код (2026-06-04)

**Уточнение диагноза.** Первоначальная гипотеза «на мобилке нет стилиста»
оказалась неверной: реальная точка входа — кнопка «AI» в шапке `Navigation`
(`md:hidden`, открывает drawer через контекст `useStylist()`), и на мобильных
она присутствует. Компонент же `FloatingStylist.tsx` (`hidden md:flex`) —
**мёртвый код**: он нигде не импортируется и не монтируется, дублирует логику
открытия и вводит в заблуждение.

**Сделано.** Удалён неиспользуемый `src/components/stylist/FloatingStylist.tsx`.
Мобильный и десктопный вход в стилист идут через `Navigation` + `useStylist()`,
drawer рендерится глобально в `ConditionalSiteLayout`.

**Файлы:** удалён `src/components/stylist/FloatingStylist.tsx`.

### Блок 2 — модель и формат вызова (2026-06-04)

**Решение пользователя:** остаёмся на Replicate (биллинг не трогаем), но ставим
более сильную модель.

**Сделано.**
- `src/lib/server/replicate-ai.ts`: модель по умолчанию переведена с
  `openai/gpt-4o-mini` на **`openai/gpt-4.1`** (заметно лучше следует
  инструкциям и держит формат «текст + JSON»). Модель теперь переопределяется
  без деплоя через env `STYLIST_LLM_MODEL`.
- Улучшено формирование prompt'а: история оформляется как явный транскрипт
  («Conversation so far: …») с ролями и пустой строкой-границей перед текущим
  запросом, чтобы модель продолжала диалог, а не пересказывала его.
- `src/components/stylist/StylistDrawer.tsx`: сообщение при 501 больше не врёт
  про «OpenAI API key» — теперь нейтральное «configure the AI provider token».

**Файлы:** `src/lib/server/replicate-ai.ts`, `src/components/stylist/StylistDrawer.tsx`.

### Блок 5 — надёжность контракта «текст + JSON» (2026-06-04)

**Проблема.** Модель иногда нарушает формат: забывает JSON-блок, пишет ID
внутри текста или просто называет товар словами — рекомендации при этом
полностью терялись (карточки не показывались).

**Сделано.** В `src/app/api/stylist/chat/route.ts` добавлена функция
`recoverSuggestions()` и шаг восстановления: если после парсинга JSON-блока не
осталось валидных ID, мы пытаемся восстановить их из сырого ответа модели —
(1) по любому ID каталога, встретившемуся в тексте дословно, и (2) по полному
названию товара, упомянутому в ответе (мин. длина 4 символа, чтобы не ловить
generic-слова). Восстановление строго ограничено `relevantProducts`, поэтому
нельзя показать товар, которого модель не имела в виду. Счётчик
`recoveredSuggestions` виден в `?debug=1`.

**Файлы:** `src/app/api/stylist/chat/route.ts`.
