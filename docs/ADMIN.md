## Коротко

- Адрес: `https://goo-fashion.com/goo-studio`. С сайта на него нет ссылок, адрес вводят вручную. `/admin` молча перекидывает на главную.
- В `robots.txt` раздел `/goo-studio/` закрыт от поисковиков. Своя аналитика сайта эту зону не записывает. PostHog не шлёт по ней просмотры страниц, но если посетитель раньше согласился на cookies на сайте, PostHog остаётся загруженным, и его автосбор кликов и запись сессий код для админки не отключает.
- Нужны вход через Clerk и права админа (см. раздел 1).
- Почти всё в админке работает через Supabase. Без него сайт показывает встроенный демо-каталог, а в админке запись выключена: кнопки неактивны с подсказкой «Requires Supabase» либо API отвечает «Database not configured».
- Долгие операции (сбор каталога, CSV-импорт, эмбеддинги, замер фона фото) идут из открытой вкладки браузера пачками. Если закрыть вкладку, работа останавливается после текущей пачки.

## 1. Доступ

### Кто может войти

Доступ проверяется в двух местах. Страницы `/goo-studio/*` проверяет `src/proxy.ts`. Каждый роут `/api/admin/*` проверяет себя сам через `requireAdmin()` из `src/lib/server/admin-auth.ts` и чужим отвечает 401.

| Способ | Где задаётся | Как снять |
|---|---|---|
| Clerk user ID (`user_…`) в `ADMIN_USER_IDS`, через запятую | переменная окружения приложения в Coolify | убрать ID из переменной и передеплоить приложение в Coolify |
| Флаг `isAdmin: true` в Clerk `publicMetadata` | супер-админ: Users → карточка пользователя → Access → Admin | тот же переключатель |

- Кто не вошёл, попадает на `/login?redirect_url=…`. Кто вошёл, но не админ, попадает на главную.
- Если `ADMIN_USER_IDS` пуст и ни у кого нет флага, в админку не попадёт никто.
- Флаг `isAdmin` читается из сессионного токена Clerk, из claim `metadata` или `publicMetadata`. По умолчанию Clerk публичные метаданные в токен не кладёт, для этого в Clerk Dashboard настраивается свой session token. **Настроено ли это на проде, нужно уточнить у CEO.** Если не настроено, переключатель в Users запишет флаг в Clerk, но в админку этого человека не пустит, и работать будет только `ADMIN_USER_IDS`. Если выданные права не подхватились сразу, пусть человек выйдет и войдёт заново.

### Супер-админ

`SUPER_ADMIN_USER_ID` — Clerk ID одного владельца. Переменная читается только на сервере.

Что может только он:
- открыть **Activity**, журнал действий админов. Пункт меню с меткой `SA` виден только ему, а API `/api/admin/audit` всем остальным отвечает 403;
- выдать или снять флаг админа (Users → Access). Админам из `ADMIN_USER_IDS` этот переключатель не нужен, у них вместо него плашка «Via env».

Его аккаунт защищён. Через админку никто, включая его самого, не может его править, банить или удалять: API отвечает 403, а в массовых действиях на странице Users его строку не выбрать.

Сам супер-админ тоже должен быть админом. На практике это значит, что его ID вписан в `ADMIN_USER_IDS`: флаг `isAdmin` ему через студию не поставить, потому что аккаунт защищён от правок (вручную в Clerk Dashboard можно, но флаг сработает только при настроенном session token, см. выше). **Вписан ли ID из `SUPER_ADMIN_USER_ID` в `ADMIN_USER_IDS` на проде, нужно уточнить у CEO.**

Если `SUPER_ADMIN_USER_ID` пуст, Activity отвечает 403 всем и выдать права админа не может никто. В шапке у супер-админа видна плашка «Super Admin» и янтарная рамка вокруг аватара.

Ещё одно правило для всех: удалить собственный аккаунт через Users нельзя.

### `GET /api/admin/me`

Отвечает любому админу `{ userId, isSuperAdmin }`, не админу — 401. По этому ответу меню, Users и Activity узнают, супер-админ ли текущий пользователь. Переменная `NEXT_PUBLIC_SUPER_ADMIN_USER_ID` больше нигде не читается. Если запрос не удался, меню показывается как обычному админу, а супер-админские API всё равно проверяют права сами.

## 2. Оболочка: меню, тема, телефон

### Меню

Список пунктов задан в `NAV_ITEMS` в `src/app/goo-studio/layout.tsx`. Группы идут в фиксированном порядке.

| Группа | Пункт | Адрес | Для чего |
|---|---|---|---|
| Overview | Dashboard | `/goo-studio` | сводка и здоровье сервисов |
| Catalog | Products | `/goo-studio/products` | товары |
| Catalog | Outfits | `/goo-studio/outfits` | образы и модерация образов покупателей |
| Catalog | Brands | `/goo-studio/brands` | список брендов и их логотипы |
| Catalog | Retailers | `/goo-studio/retailers` | правила «домен → название магазина» |
| Catalog | Audit | `/goo-studio/audit` | подозрительная разметка товаров |
| Catalog | Duplicates | `/goo-studio/duplicates` | один товар в нескольких карточках |
| Catalog | Categories | `/goo-studio/categories` | дерево категорий и подкатегорий |
| Content | Blog | `/goo-studio/blog` | статьи блога |
| Imports | Import | `/goo-studio/import` | импорт CSV-фида (Awin) |
| Imports | Parser | `/goo-studio/parser` | сбор товаров с сайтов магазинов |
| — | ↳ Collect | `/goo-studio/parser/collect` | приёмник для расширения Chrome (своего пункта в меню нет) |
| Users | Users | `/goo-studio/users` | аккаунты Clerk: план, бан, права, удаление |
| Users | Waitlist | `/goo-studio/waitlist` | архив адресов из снятой формы ожидания |
| Users | Email | `/goo-studio/email` | рассылки через Resend |
| Data | Analytics | `/goo-studio/analytics` | собственная аналитика сайта |
| Data | Subscriptions | `/goo-studio/subscriptions` | подписки, выручка, здоровье биллинга |
| Data | Activity `SA` | `/goo-studio/activity` | журнал действий (только супер-админ) |

| System | Prompts | `/goo-studio/prompts` | тексты промтов для AI |

- **Customize** (внизу меню) — порядок пунктов внутри группы. Пункт перетаскивается мышью или двигается стрелками, группы остаются на местах. «Reset to default» возвращает исходный порядок. Изменения сохраняются сразу, в `localStorage` браузера (ключ `goo-admin-nav-order`), поэтому на другом устройстве порядок будет свой. Новые пункты меню сами добавляются в конец своей группы.
- Стрелка в строке логотипа сворачивает меню до иконок. Это работает только на компьютере, и после перезагрузки меню снова развёрнуто.
- **Back to site** возвращает на сайт.

### Тема

Кнопка «Dark mode» / «Light mode» внизу меню. Тема админки не зависит от темы сайта, по умолчанию светлая. Выбор хранится в `localStorage` (ключ `goo-admin-theme`): у каждого браузера свой, между открытыми вкладками синхронизируется. Если хранилище заблокировано (приватный режим), выбор действует до перезагрузки.

Как устроено: у корня админки стоит класс `admin-theme-light` или `admin-theme-dark`, а в `src/app/globals.css` эти классы заново объявляют все цветовые токены.

### Телефон (экран уже 768 px)

- Боковое меню прячется. Кнопка-гамбургер слева в шапке открывает его выезжающей панелью (drawer) шириной 280 px с затемнённым фоном.
- Панель закрывается по тапу на пункт, на крестик или на затемнённый фон, по Esc, при любой смене страницы (в том числе жестом «назад»), а также при повороте экрана, если он стал шире 768 px. Пока панель открыта, страница под ней не прокручивается. После закрытия крестиком, тапом по фону или по Esc фокус возвращается на гамбургер.
- В хлебных крошках скрыто «Admin», чтобы осталось место для названия страницы. Уже 640 px имя и email админа в шапке тоже скрыты, остаётся аватар с инициалами.
- Кнопки и поля не ниже 40 px. Текст в полях 16 px, иначе iOS Safari зумит страницу при вводе.
- В Customize перетаскивание работает только мышью, на телефоне пункты двигают стрелками.
- Широкие таблицы (Products, Outfits, Users, Subscriptions и др.) прокручиваются вбок. Вкладки парсера тоже прокручиваются вбок.

## 3. Разделы

Во всех разделах действуют общие правила:
- удаления, откаты и массовые правки спрашивают подтверждение. Обычно это системный диалог браузера, у рассылки — вторая кнопка **Confirm send**. У импортов (CSV, Collect catalog) отдельного подтверждения нет: у CSV его роль играет шаг предпросмотра, у обоих есть кнопка **Stop**;
- ошибки показываются тостом или плашкой с текстом ответа сервера;
- в журнал Activity пишется только то, что перечислено в разделе 4.

### Dashboard — `/goo-studio`

Сводка без действий, меняющих данные.
- Карточки **Products / Outfits / Users / Brands**. У первых трёх есть прирост «vs last month»: с начала месяца против тех же дней прошлого месяца. У Brands прироста нет, только среднее число товаров на бренд.
- **System Health.** Supabase и Clerk проверяются настоящим запросом. OpenAI — есть ли ключ, в env или в Settings. Replicate, Monobank, Resend — только наличие переменной окружения: живость самого сервиса не проверяется.
- Последние 6 регистраций, 6 образов и 6 товаров. Кнопка **Refresh**.

Ограничения: если метрика не загрузилась, вместо неё стоит «—», а не ноль. Рост пользователей считается по 200 самым новым аккаунтам. Если за этот и прошлый месяц регистраций больше 200, прошлый период недосчитан и рост выглядит выше, чем есть.

### Products — `/goo-studio/products`

Все товары каталога, включая неосновные цветовые варианты.

**Найти:**
- поиск по названию, бренду и категории;
- чипы категорий и подкатегорий (берутся из дерева Categories);
- фильтры по бренду, цветовой группе, стилю и полу;
- **Missing** — показать товары, у которых нет подкатегории, цветового фильтра, цветов, стиля, пола, описания, размеров или фото;
- **New only**, сортировка, **Clear**.

Ссылка вида `/goo-studio/products?search=<название>` открывает таблицу уже отфильтрованной. Так на товар ведёт Audit.

**Действия с одним товаром:**
- **Add Product / Edit / Duplicate** — форма товара: фото, основные поля, категория и подкатегория, размеры, цены, «Where to buy», цвета и цветовые фильтры, цветовые варианты.
  - Фото по внешней ссылке копируется в наше хранилище.
  - «Where to buy» выбирает магазины из библиотеки: бренды с логотипами из Brands плюс магазины из Retailers.
  - **Suggest fields** подсказывает категорию, подкатегорию, пол и цветовые фильтры по названию, глядя на то, как разложен остальной каталог. AI здесь не используется.
- **Кадрирование фото** — иконка в строке. Требует миграцию `023_product_crop_data.sql`.
- **Download card** — карточка товара картинкой.

**Действия с выделением** (галочки; Shift выделяет диапазон):
- **Group variants** (от двух товаров) — связать товары как цвета одного, выбрать основной.
- **Edit N** — массовая правка: бренд, пол, подкатегория (категория подставится по дереву), стиль и цветовые фильтры (для обоих — заменить или добавить), в названиях — найти и заменить, приставка в начале и в конце. Пустое поле остаётся как было.
- **Delete N**.

**Кнопки в шапке:**
- **Fix categories** — переклассифицирует товары без подкатегории. Сначала идёт сухой прогон, и диалог показывает, что и куда поменяется и что защищено. Разложенное руками не трогается. **Undo fix** откатывает последний прогон; товары, изменённые после него, остаются как есть.
- **Photo backdrops** — измеряет цвет фона фото, чтобы карточка добивалась этим цветом, а не белым. Сначала пробный замер 40 фото без сохранения, затем подтверждение и прогон: по выделению или по всем ещё не измеренным товарам. **Undo backdrops** откатывает последний прогон. Нужна миграция `015_product_bg_color.sql`.
- **Download cards** — карточки картинками одним ZIP: выделенные, а если выделения нет — всё, что показывает фильтр.

Внимание:
- С подтверждением работают удаление (одного и массовое), Edit N, Fix categories, Undo fix, Photo backdrops, Undo backdrops и разгруппировка вариантов.
- Товар, который входит в образ, не удаляется: сервер отвечает 409 и называет образы. При массовом удалении такие строки остаются выделенными.
- Если в БД нет какой-то колонки (не прогнана миграция), товар сохраняется без неё, и тост об этом говорит. Какие миграции не хватает, показывает Settings → Database schema.
- Журнал: `products.created`, `products.updated` (правка, кадрирование, группы вариантов), `products.deleted` (массовое удаление пишет по записи на товар), `products.bulk_edited`, `products.recategorized`, `products.recategorize_undone`, `products.bg_color_sampled`, `products.bg_color_undone`.

### Outfits — `/goo-studio/outfits`

Две вкладки.

**Outfits** — образы на сайте.
- **Add Outfit / Edit**:
  - до 6 вещей из каталога, у каждой роль hero, secondary или accent; в подборщике видно 60 товаров, остальные ищутся поиском;
  - название, повод, сезон, описание, стиль;
  - обложка: загрузить файл или вставить ссылку;
  - цена считается сама по вещам.
- **Звёздочка** «Feature on homepage». Карусель образов на главной показывает отмеченные, новые первыми, до 9 штук. Если отмеченных нет, показываются самые новые образы.
- **Download cards** — образы и карточки их вещей одним ZIP.
- Удаление одного образа или выделенных — с подтверждением, без отмены.

**Pending** — образы, которые покупатели прислали из «Мои образы». Число на вкладке — сколько ждут проверки.
- Название, описание, повод, сезон и стиль можно поправить прямо в окне проверки. Очищенное поле означает «оставить как прислал покупатель».
- **Approve — add to Outfits** создаёт образ.
- **Reject** — с подтверждением. Образ уходит из очереди и не публикуется.
- Если образ уже обработал другой админ, очередь обновится сама.

Журнал: `outfits.created`, `outfits.updated` (включая звёздочку), `outfits.deleted`, `looks.approved`, `looks.rejected`.

### Brands — `/goo-studio/brands`

Список брендов для автоподстановки в форме товара и логотипы магазинов.
- Добавить бренд, найти бренд.
- **Логотип:** загрузка картинки до 5 МБ. Логотип показывается рядом с магазином с таким же названием в «Where to buy». **Удаление логотипа** — с подтверждением; после него на сайте показывается иконка сайта магазина.
- **Удалить бренд** — с подтверждением. Бренд пропадает только из списка: у товаров строка бренда остаётся как была.
- Журнал: `brands.created`, `brands.deleted`, `brands.logo_updated`, `brands.logo_removed`.

### Retailers — `/goo-studio/retailers`

Одно правило на домен: как называется магазин, официальный ли это магазин бренда (метка Official), какой пол подставлять новым импортам, когда название, ссылка и хлебные крошки товара о поле молчат (Men — «All» у магазина мужское, Unisex — «All» для всех, Women — магазин продаёт только женское; у товаров, где пол уже стоит, он не меняется). Без правила название и «официальность» угадываются по ссылке, поэтому импорт и называет магазины по хосту.
- **Rules** — правила: добавить, изменить, удалить. Новое правило для домена, у которого правило уже есть, заменит старое, и перед этим спросят подтверждение.
- **Apply to existing** переписывает название магазина и метку Official у уже импортированных товаров этого домена и его поддоменов (кроме поддоменов со своим правилом). Подтверждение предупреждает, что ручные исправления названия на отдельных товарах тоже будут перезаписаны. Если часть товаров не обновилась, нажмите ещё раз.
- **Domains without a rule** — домены, которые встречаются в товарах, но правила не имеют, с их текущими названиями. «Add rule» подставляет домен в форму.
- Правила действуют на все товары, импортированные после сохранения. Удаление правила уже импортированные товары не меняет.
- Ограничения: список доменов собирается сканированием каталога с потолком, и если потолок достигнут, страница это пишет. Без миграции `018_retailer_domains.sql` сохранять нечего, и страница об этом предупреждает.
- Журнал: `retailer_domain.saved`, `retailer_domain.deleted`, `retailer_domain.applied`.

### Audit — `/goo-studio/audit`

Товары, у которых разметка выглядит неверной. Секции: подкатегория, которой нет в дереве; категория противоречит подкатегории; название говорит о другом типе вещи или другой подкатегории; товар разложен не так, как почти одинаковые соседи; пол по названию; вероятно, не хватает цветового фильтра. Точные проверки помечены отдельно, остальные — только подсказки.

- **Apply** исправляет одно поле одного товара: категорию, подкатегорию, пол или цветовой фильтр (фильтр только добавляется). Там, где стоит «Edit by hand», исправление делается вручную: ссылка открывает товар в Products.
- **Dismiss** — «подсказка неверна, больше не показывать». Кнопка **Dismissed (N)** показывает отклонённые подсказки, и их можно вернуть (**Restore**).
- **Re-check** — прогнать проверку заново.
- Массового «применить всё» нет намеренно: каждое исправление — решение по конкретному товару.
- Ограничения: в секции видно до 300 находок, остальные только посчитаны. Чтобы Dismiss запоминался, нужна миграция `012_label_audit_dismissals.sql`.
- Журнал: `products.label_fixed`, `products.label_dismissed`, `products.label_restored`.

### Duplicates — `/goo-studio/duplicates`

Один и тот же товар, заведённый несколькими карточками. Поиск применяет ко всему каталогу ту же проверку «это одна вещь», что и сбор каталога. Совпадения: одинаковый штрихкод, одинаковый код производителя, либо одна модель одного бренда в тех же цветах у разных магазинов по сопоставимой цене.

- В группе выбирается карточка **Keep**. По умолчанию предложена карточка с официального магазина бренда. Галочки определяют, какие карточки вливать в неё.
- **Merge N into kept** — с подтверждением. Магазины и цены переносятся на оставляемую карточку, её пустые поля заполняются, лайки, образы и луки переезжают к ней, остальные карточки **удаляются. Отмены нет.**
- **Not the same item** / **Unticked aren't the same (N)** — с подтверждением запоминает, что это разные вещи, и группа больше не предлагается. Из интерфейса это не отменить. Для запоминания нужна миграция `012_label_audit_dismissals.sql`; слияние работает и без неё.
- **Re-scan** — поискать заново.
- Журнал: `products.duplicates_merged`, `products.duplicates_dismissed`.

### Categories — `/goo-studio/categories`

Дерево категорий: группы, а в них подкатегории. Каждая подкатегория указывает на одно из значений категории, которые хранятся у товара. Дерево управляет фильтрами каталога, формой товара и хлебными крошками.

- **Подкатегории:** добавить, переименовать, перенести в другую группу, сменить значение категории, задать свои размеры (пустой список означает «брать сетку размеров категории»), двигать вверх и вниз.
- Правки подкатегории применяются и к товарам:
  - переименование переименовывает подкатегорию у всех её товаров;
  - смена значения переносит товары в другую категорию;
  - удаление (с подтверждением и числом затронутых товаров) снимает подкатегорию с товаров: они остаются в каталоге и отвечают на фильтр всей группы.
- **Группы:** добавить, переименовать, удалить (с подтверждением). Удалить можно только пустую группу, иначе сервер попросит сначала перенести или удалить подкатегории.
- **Своё значение категории** (не из встроенных) разрешено, но у товаров с ним не будет конструктора образов, автоматической классификации при импорте и сетки размеров. Страница предупреждает об этом, когда такое значение выбрано.
- Страница только для чтения, если нет Supabase или не прогнаны миграции `011_category_tree.sql` и `013_subcategory_sizes.sql`. Тогда показывается дерево, зашитое в код.
- Журнал: `categories.updated` на каждую правку.

### Blog — `/goo-studio/blog`

Статьи блога: список с поиском и статусом Published или Draft.
- **Редактор:** заголовок, обложка по ссылке, анонс, текст (пустая строка между абзацами, для заголовков и ссылок — HTML), переключатель Published/Draft, slug, категория, время чтения, автор, **Publish date override**, meta title/description, картинка Open Graph.
- **AI Draft** — черновик через OpenAI. Два режима: «из URL» (чужая статья переписывается в наш пост) и «из брифа» (от 12 символов). Сгенерированный текст всегда открывается как черновик, публикация — отдельным переключателем. Промты генерации правятся в Prompts.
- **Удаление** — с подтверждением, без отмены.
- Журнал: `blog.created`, `blog.updated`, `blog.deleted`. Сама генерация черновика в журнал не пишется.

### Import — `/goo-studio/import`

Импорт партнёрского CSV-фида. Поддерживаются колонки формата Awin, их список показан на странице. Строка годится для импорта, если в ней есть название, цена и ссылка (`aw_deep_link` или `product_url`). Распроданная строка годится только для обновления уже заведённого товара.

Шаги:
1. Выбрать файл `.csv` или `.csv.gz`. Файл читается в браузере и на сервер целиком не отправляется.
2. Выбрать мерчантов.
3. Предпросмотр. Сервер отмечает, какие ссылки уже есть в каталоге. План делит строки на новые товары, обновления существующих и пропуски (товар распродан и в каталоге его нет).
4. Импорт пачками, каждая пачка проходит общий конвейер импорта: копирование фото (если оно включено в Parser → Fetch & Anti-bot), замер цвета, поиск дублей. Кнопка **Stop** есть. После 3 неудачных пачек подряд импорт останавливается сам.

Что происходит с товарами:
- Существующий товар (по ссылке) не перезаписывается целиком: обновляются только цена, магазины с наличием и размеры. Название, категория, описание, теги, фото и группировка, которые правили вручную, остаются.
- Если в БД нет колонки, товар сохраняется без неё, и страница об этом предупреждает.

Журнал: `import.csv`, одна запись на пачку, в которой что-то создано, обновлено или слито, со счётчиками created, updated, merged, skipped и errors.

### Parser — `/goo-studio/parser`

Сбор товаров со страниц магазинов. Страница читает JSON-LD, OpenGraph и микроразметку. Если структурированных данных нет, подключается AI (OpenAI), если включён. Фото копируются в наше хранилище, если включено. Четыре вкладки.

- **Collect catalog.** Вставить ссылку на категорию, страницу бренда или один товар, задать **Max products** (до 2000) и **Listing pages** (до 20), переключатели AI и копирования фото, нажать **Collect**. Прогон идёт пачками по 5 товаров, есть **Stop**. Если магазин отказал (401/403/429/503), появятся две кнопки: **Collect with the extension** и **Paste page instead**.
- **Parse URL.** Один товар или страница-листинг, с предпросмотром.
  - Для одного товара открывается форма правки и кнопка **Import product**.
  - Для листинга — сетка товаров с выбором («Select valid») и массовым импортом либо список ссылок и «Parse first N».
  - Панель **Paste page** обходит блокировку: букмарклет перетаскивается на панель закладок, товар открывается в своём браузере, после клика по букмарклету HTML страницы вставляется в поле. Поле Product URL при этом нужно заполнить, иначе каталогу не к чему привязать товар.
- **Site Recipes.** Правила для отдельных сайтов, по хосту: подмена бренда, категории и пола, регулярные выражения для полей, заметки. Изменения применяются только по **Save recipes**. Удаление рецепта тоже вступает в силу только после сохранения.
- **Fetch & Anti-bot.** Как скачивать страницы: Direct, ScrapingBee, ScraperAPI, ZenRows или свой endpoint. Здесь же таймаут, Render JS, Impersonate (под какой браузер маскироваться), когда звать AI (Auto — только если не хватает названия, цены или фото; Always — всегда, дороже), копирование фото в хранилище и API-ключ провайдера. Ключ из `PARSER_FETCH_API_KEY` в env отсюда не меняется. Ключ, сохранённый в БД, удаляется с подтверждением.

Внимание:
- Повторный сбор того же URL (Collect catalog, Parse URL, расширение) обновляет карточку, а не создаёт вторую. При этом поля перезаписываются данными со страницы. Остаются только стиль и пол, если они уже были заполнены. Остальные ручные правки (название, описание, фото, категория) будут потеряны.
- AI и провайдеры скачивания платные. AI в Collect catalog тратит вызов модели на каждый товар без структурированных данных.
- Несохранённые правки на вкладках Site Recipes и Fetch & Anti-bot переживают переключение вкладок, но не перезагрузку страницы.
- Журнал: `parser.crawl_batch` (одна запись на пачку Collect catalog), `parser.product_imported` (импорт из Parse URL), `parser.config_updated` (сохранение рецептов и настроек скачивания).

#### Collect — `/goo-studio/parser/collect`

Приёмник для расширения Chrome «Goo Collect». Расширение открывает страницы магазина в браузере админа, то есть с его адресом и куки, поэтому магазин его не блокирует. Вкладка приёмника импортирует товары от имени вошедшего админа. Ключей и токенов в расширении нет.

- Установка один раз: `chrome://extensions` → Developer mode → **Load unpacked** → папка `extension/` из репозитория. Подробно — в [extension/README.md](../extension/README.md).
- Пока идёт прогон, вкладку приёмника **не закрывать**. Статус «Extension connected» или «Waiting for the extension» показывает, видит ли вкладка расширение.
- В каждой строке результата видно, сколько фото перенесено, как пересчитана цена (курс валюты), откуда взят бренд, и было ли слияние с уже существующей карточкой (новый магазин у старой карточки).
- **Stop** останавливает сразу: вкладка перестаёт принимать товары, даже если расширение ещё на середине страницы. **Clear** сбрасывает список.
- Страница показывает, прочитан ли `robots.txt` и какой в нём crawl-delay. Расширение соблюдает `Disallow` и темп из robots.txt.
- Журнал: `parser.collect_ingest`, одна запись на каждый импортированный или обновлённый товар.

### Users — `/goo-studio/users`

Аккаунты Clerk, по 25 на страницу.
- Поиск по имени и email. Фильтры по плану (free, basic, pro, premium) и по статусу (active, banned, locked). Счётчики сверху считаются по всем пользователям, а если Clerk отдал не всех, помечены «of newest N». «Locked» — блокировка входа на стороне Clerk (например, после неудачных попыток входа); в интерфейсе админки её не снять.
- **Массовые действия** по выделенным (выделение сохраняется при листании страниц): Ban, Unban, Set plan, Delete. Все с подтверждением. Запрос идёт отдельно на каждого пользователя, в итоге показывается «N of M succeeded», а неудачные остаются выделенными.
- **Карточка пользователя:**
  - статистика: сообщения стилисту сегодня и всего, AI-картинки, луки;
  - **Reset today's limit** снимает сегодняшний лимит стилиста. **Reset all-time** — с подтверждением: удаляет всю историю сообщений стилиста этого пользователя, она пропадёт и из графика в Analytics;
  - имя и фамилия, план, Admin (только для супер-админа), Banned — сохраняются по **Save changes** без дополнительного подтверждения;
  - **Delete user** — с подтверждением.

Внимание:
- **План меняется только в Clerk, биллинг не меняется.** Если у пользователя активная подписка, об этом предупреждают. Списания продолжатся, а следующее продление вернёт платный план. Кнопки отмены подписки в админке нет, см. [BILLING.md](../BILLING.md).
- Удаление необратимо: аккаунт Clerk удаляется. Если есть активная подписка, сначала выключается автопродление, чтобы с карты больше не списывали, и подтверждение об этом говорит.
- Журнал: `user.name_updated`, `user.plan_changed`, `user.admin_granted`, `user.admin_revoked`, `user.banned`, `user.unbanned`, `user.deleted`, `stylist_usage.reset`.

### Waitlist — `/goo-studio/waitlist`

Архив адресов из формы ожидания. Публичную форму сняли в сентябре 2026, новые адреса не приходят.
- **Copy all** копирует все адреса в буфер, по одному на строку. Их можно вставить в Email → Custom emails.
- Удаление адреса — с подтверждением, без отмены.
- Журнал: `waitlist.deleted`.

### Email — `/goo-studio/email`

Рассылки через Resend.

**Настройка:**
- Вверху показан статус: настроен ли `RESEND_API_KEY` и с какого адреса уходят письма (`RESEND_FROM_EMAIL`, по умолчанию `GOO Fashion <hello@goo-fashion.com>`).
- **Аудитория:** All users, один из планов (Free, Basic, Pro, Premium) или Custom emails — вставленный список адресов. У All users и у планов видно число получателей из Clerk.

**Письмо:**
- Тема и текст. Разметка: `#` и `##` для заголовков, `-` для списка, `**жирный**`, `*курсив*`, `` `код` ``; подсказка раскрывается на странице.
- **Write with AI** пишет текст через OpenAI по теме и брифу.
- **Шаблоны:** сохранить, загрузить (с подтверждением, если это затрёт текущий текст), удалить (с подтверждением).
- **Show email preview** показывает письмо так, как его соберёт сервер.

**Отправка:**
- **Send test to me** отправляет письмо только на первый email текущего админа.
- **Send to N recipients** → **Confirm send**. Отправка идёт пачками по 100 с паузами. В итоге показывается, сколько отправлено и какие пачки упали.

Внимание:
- Если отправка оборвалась (таймаут, сеть), часть писем могла уже уйти. Прежде чем повторять, проверьте дашборд Resend, иначе люди получат письмо дважды.
- В «All users» и в аудитории плана попадают все аккаунты Clerk с email, фильтра по бану нет.
- Ссылки отписки в письме нет. В подвале только строка о том, почему человек получил письмо.
- Журнал: `email.sent`, только для настоящей рассылки. Тестовое письмо, шаблоны и AI-текст в журнал не пишутся.

### Analytics — `/goo-studio/analytics`

Собственная аналитика сайта: таблицы `page_views`, `web_vitals`, `analytics_events` в Supabase, для AI Usage ещё `stylist_daily_usage` (Vercel Analytics удалён). Периоды 24h, 7d, 30d, 90d, кнопка Refresh.

Разделы:
- сводка: активные сейчас (сессии за последние 5 минут), просмотры, сессии, среднее и p75 время загрузки, сессии за 24h, 7d и 30d;
- **AI Usage** — сообщения стилисту и генерации картинок;
- **Traffic Over Time**;
- **Activity by Hour (Kyiv time)**;
- **Core Web Vitals — p75**;
- **Audience**;
- **Conversion Funnel (sessions)**;
- **Top Content** — страницы, товары, образы;
- **Traffic Sources & Search** — рефереры, UTM, поисковые запросы на сайте;
- **Event Breakdown**.

Внимание:
- Всё, что считается по `session_id`, — это сессии, а не люди: после 30 минут бездействия начинается новая сессия.
- Визиты в `/goo-studio`, запросы к `/api/`, `robots.txt` и `sitemap.xml` не считаются.
- Страница читает максимум 200 000 строк на таблицу. Если строк больше, появляется плашка, что самый старый кусок периода недосчитан.

### Subscriptions — `/goo-studio/subscriptions`

Подписки и деньги. Страница только для просмотра, действий на ней нет, отменить подписку отсюда нельзя.
- **Плашка вверху** появляется, если таблица `billing_events` читается и cron продления не запускался 36 часов или не запускался ни разу. В ней написано, что проверить в Coolify. Пока cron стоит, никто не продлевается, не списывается и не понижается.
- **KPI:** заработано всего и за месяц, MRR, активные подписчики (и сколько из них не продлятся), past due, canceled, pending checkout, разбивка по планам.
- **Billing health.** Каждая карточка горит красным, если что-то не так:
  - **Renewal cron** — когда cron запускался в последний раз;
  - **Active without card** — активные подписки без сохранённой карты: продление их пропускает, то есть это платные планы бесплатно;
  - **Overdue** — оплаченный период кончился, продления не было;
  - **Failed charges** — неудачные списания подряд.
- **Subscribers** — таблица подписок.
- **Transaction log** — последние 200 событий биллинга. Служебные отметки «cron запускался» в нём скрыты. «Cron broken» означает, что не задан `CRON_SECRET`.
- Если нет таблицы `billing_events` (миграция `supabase-migration-billing-events.sql`) или её не удалось прочитать, страница об этом пишет: карточка Renewal cron показывает «unknown», а выручка и журнал транзакций неполные.
- Суммы в долларах приблизительные, по курсу `BILLING_USD_UAH_RATE`. Списания всегда в гривнах.

### Activity — `/goo-studio/activity` (только супер-админ)

Журнал действий админов, см. раздел 4. Фильтр по админу (кнопки-«пилюли», список всех, кто когда-либо писал в журнал) и по действию (выпадающий список по группам). По 50 записей, дальше **Load more**. В строке: кто, что сделал, над чем (тип и ID), подробности (например, «план free → pro») и когда. Удаления и бан подсвечены красным, выдача прав и одобрение образов зелёным, чувствительные изменения (план, снятие прав, новый ключ API, рассылка, сброс лимита) янтарным. Обычный админ, открывший адрес напрямую, увидит «Access restricted to super admin only».

### Settings — `/goo-studio/settings`

Карточки:
- **Database schema** — какие таблицы и необязательные колонки код ожидает, каких не хватает и какие миграции прогнать. Кнопка **Re-check**. Недостающая колонка не ломает сохранение, но молча выключает свою функцию, поэтому после деплоя сюда стоит заглянуть.
- **Homepage showcase** — 4 шага витрины на главной: Choose items (1 товар), Build your look (до 3 товаров), Generate preview (1 образ), Shop the look (до 3 товаров). Сохраняется кнопкой и попадает на главную при следующей загрузке. Пока текущий выбор не загрузился, сохранить нельзя, чтобы пустой выбор не затёр живой.
- **AI Stylist showcase** — блок стилиста на главной: до 2 образов в чате, товар «Featured product», до 6 дополнительных магазинов в «Where to buy».
- **OpenAI API key** — ключ для функций на OpenAI: черновики блога, AI-текст писем, AI-разбор страниц в парсере, баг-репорты, эмбеддинги (смысловой поиск стилиста). Чат стилиста и генерация картинок идут через Replicate (`REPLICATE_API_TOKEN`), этот ключ на них не влияет.
  - Если задан `OPENAI_API_KEY` в env, используется он, а менять и удалять его здесь нельзя, только проверить (**Test Key**).
  - Иначе ключ хранится в таблице `settings` (миграция `024_settings.sql`): **Update**, **Test Key**, **Clear** (с подтверждением).
- **Embeddings** — сколько товаров имеют вектор для смыслового поиска стилиста и сколько нет. Импорт векторы не создаёт, поэтому после больших импортов нужна догрузка: кнопка с подтверждением, запросы к OpenAI за счёт ключа выше, пачками, с остановкой между пачками. Чат ищет по смыслу только при включённом на сервере `STYLIST_SEMANTIC_SEARCH`, иначе по ключевым словам.

Журнал: `settings.homepage_showcase_updated`, `settings.homepage_stylist_updated`, `settings.api_key_updated`, `settings.api_key_deleted`. Проверка ключа и догрузка эмбеддингов в журнал не пишутся.

### Prompts — `/goo-studio/prompts`

Тексты промтов для AI. Хранятся в таблице `settings`, код по умолчанию лежит в `src/lib/server/prompt-defaults.ts`.
- **Content:** Blog — System, Blog — From URL, Blog — From brief, Email — AI Write.
- **Image Gen:** Fidelity block, Mannequin, Flatlay, Try-on — генерация картинок в конструкторе.
- Сохранить можно только текст, в котором остались все обязательные плейсхолдеры. У каждого промта свои, они подписаны на карточке: `{{content}}` (Blog — From URL), `{{brief}}` (Blog — From brief), `{{subject}}` и `{{brief}}` (Email — AI Write), `{{items}}` (Mannequin, Flatlay, Try-on). `{{url}}` и `{{fidelity}}` подставляются, если они есть, но обязательными не считаются. Пустой текст равен сбросу. Кнопка сброса к умолчанию спрашивает подтверждение.
- Журнал: `settings.prompt_updated`, `settings.prompt_reset`.

## 4. Журнал действий (Activity)

**Где хранится.** Таблица `admin_audit_log` (описана в `supabase-schema.sql`). Пишет её `logAdminAction()` из `src/lib/server/audit.ts`. Email админа подставляется из Clerk автоматически. Запись журнала никогда не блокирует само действие: если она не удалась, ошибка уходит только в лог сервера (`[audit] could not record …`). Без Supabase журнал не пишется вообще.

## 5. Типовые сценарии

### 5.1. Добавить товары из магазина

Выбор способа:

| Ситуация | Способ |
|---|---|
| Магазин не блокирует сервер | Parser → **Collect catalog** |
| Магазин блокирует сервер, нужен весь каталог | расширение Chrome + `/goo-studio/parser/collect` |
| Нужен один товар, магазин блокирует | Parser → Parse URL → **Paste page** (букмарклет) |
| Есть партнёрский CSV-фид (Awin) | **Import** |

**Collect catalog:**
1. Parser → Collect catalog → вставить ссылку на категорию или страницу бренда.
2. Задать Max products и Listing pages. Для первого раза лучше небольшое число.
3. Решить про AI (платно) и копирование фото. Значения по умолчанию берутся из вкладки Fetch & Anti-bot. Скопированные фото не зависят от сайта магазина.
4. **Collect**, дождаться, просмотреть статусы. Если пришёл отказ, нажать **Collect with the extension**.

**Расширение:**
1. Один раз установить (см. раздел 3, Collect).
2. Открыть `/goo-studio/parser/collect`, оставить вкладку открытой.
3. В другой вкладке открыть страницу категории магазина, нажать иконку Goo, указать число товаров (до 2000) и адрес студии, если он не подставился, нажать **Collect this store** и разрешить доступ к магазину.
4. Следить за счётчиком во вкладке приёмника.

**CSV:** Import → файл → мерчанты → предпросмотр, где видно, сколько создастся и сколько обновится → импорт. Уже заведённые товары обновятся только по цене, магазинам и размерам.

**После любого импорта:**
1. **Duplicates** → Re-scan: разобрать дубли (5.2).
2. **Retailers** → «Domains without a rule»: завести правила новым магазинам и при необходимости «Apply to existing».
3. **Products** → фильтр Missing (подкатегория, пол, цветовой фильтр) и **Audit**: поправить разметку (5.3).
4. **Settings → Embeddings**: догрузить векторы новым товарам.
5. Помнить: повторный сбор того же URL перезаписывает ручные правки, кроме стиля и пола.

### 5.2. Разобрать дубли

1. Catalog → **Duplicates** → **Re-scan**.
2. В каждой группе проверить по фото, названию и магазинам, что это действительно одна вещь. Причина совпадения подписана: штрихкод, код производителя или модель и цвета.
3. Выбрать **Keep**. Обычно это предложенная карточка с официального магазина. Снять галочки с карточек, которые к группе не относятся.
4. **Merge N into kept** → подтвердить. Слияние необратимо: остальные карточки удаляются, их магазины, лайки, образы и луки переходят к оставленной.
5. Если группа ложная, нажать **Not the same item**, а если ложна часть группы — **Unticked aren't the same**. Больше такое не предложат.

### 5.3. Поправить категории

- **Структура** (новая подкатегория, переименование, размеры): Categories. Помнить, что правка подкатегории сразу применяется ко всем её товарам.
- **Точечно**: Audit → Apply по одному товару или Dismiss для ложных подсказок. «Edit by hand» и ссылка на товар ведут в форму товара.
- **Массово**:
  - Products → Missing: No subcategory, при необходимости фильтр по категории → выделить → **Edit N** → подкатегория. Категория подставится по дереву.
  - Или **Fix categories**: автоматически разложит товары без подкатегории, показав план заранее. Если результат не нравится, **Undo fix** откатит последний прогон.
- Проверить результат: Audit → **Re-check**.

### 5.4. Сделать рассылку

1. Email: убедиться, что Resend настроен (зелёный статус вверху).
2. Выбрать аудиторию. Для адресов из листа ожидания: Waitlist → **Copy all** → Custom emails.
3. Написать тему и текст, при желании через **Write with AI** или из шаблона. Проверить **Show email preview**.
4. **Send test to me** → проверить письмо в своём ящике.
5. **Send to N** → **Confirm send**. Дождаться результата и не закрывать вкладку.
6. Если есть упавшие пачки или отправка оборвалась, сначала проверить дашборд Resend, а потом решать, кому досылать. Повторная отправка всей аудитории приведёт к дублям.

### 5.5. Проверить здоровье биллинга и cron

1. **Dashboard → System Health**: Monobank и Resend зелёные, то есть переменные заданы. Это не проверка связи с сервисами.
2. **Subscriptions**:
   - нет плашки о cron вверху;
   - **Renewal cron** зелёный: последний запуск меньше 36 часов назад;
   - **Active without card**, **Overdue**, **Failed charges** равны нулю или объяснимы;
   - в **Transaction log** нет «Cron broken» и «Ledger error».
3. Если cron стоит. Прод живёт на Coolify, и крон из `vercel.json` там не работает. Продление запускает **Scheduled Task в Coolify**: раз в день `GET /api/billing/cron/renew` с заголовком `Authorization: Bearer $CRON_SECRET`. Проверить в Coolify:
   - задача существует и её запуски успешны;
   - `CRON_SECRET` задан в окружении приложения, иначе каждый вызов получает 401, а на почту уходит алерт.

   Точная команда и расписание — в [BILLING.md → Renewal cron on Coolify](../BILLING.md#renewal-cron-on-coolify). Существует ли задача на проде сейчас, нужно уточнить у CEO.
4. Не запускать продление вручную «для проверки» просто так. Ручной вызов — это настоящее списание со всех, у кого подошёл срок. Два запуска в день могут списать дважды.

## 6. Для разработчика

- **Где код:**
  - страницы — `src/app/goo-studio/<раздел>/page.tsx`;
  - оболочка (меню, тема, drawer, Customize) — `src/app/goo-studio/layout.tsx`;
  - API — `src/app/api/admin/**`; часть действий админки ходит в общие роуты (`/api/products`, `/api/outfits`, `/api/blog`, `/api/brands`, `/api/categories`, `/api/looks/*`), которые сами проверяют `requireAdmin()` на запись.
- **Новый раздел:**
  1. Пункт в `NAV_ITEMS` с `category`; `superAdminOnly: true`, если раздел только для супер-админа.
  2. Вложенная страница без своего пункта в меню — запись в `SUBPAGE_TITLES`, чтобы у неё была хлебная крошка.
  3. API — `requireAdmin()` (или `requireSuperAdmin()`) первой строкой.
- **Новое журналируемое действие:**
  1. Добавить строку в `AdminAction` (`src/lib/server/audit.ts`).
  2. Добавить подпись в `ACTION_LABELS` в `src/app/goo-studio/activity/page.tsx`; TypeScript не даст забыть.
  3. Вызвать `logAdminAction()` после успешной записи, не до неё.
- **UI** — только рецепты `DESIGN_SYSTEM.md` §9 и чеклист §10. Цвета — через CSS-переменные. Статусы — только три: красный, янтарный, зелёный.
- **Настройки админа** (тема, порядок меню) живут только в `localStorage` браузера. На сервер они не попадают.
- **В репозитории есть файлы, которых нет в меню и которые ждут удаления с разрешения CEO:** `src/app/goo-studio/image-tools`, `src/app/api/admin/image-tools`, `src/app/api/admin/hero-image`, `src/app/api/admin/email/preview`, `src/app/api/products/bulk`. Ими не пользоваться и не развивать.
